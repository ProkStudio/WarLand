# Открытая альфа: зашифрованный вход без Mojang

Статус: реализация для проверки, не объявление развёртывания или полной готовности.
Пользователь требует вход для всех без whitelist и владельца `egorkrid666` (#25/#29).

## Выбор режима

Новый dedicated Fabric runtime запускается с `-Dwarland.encryptedOffline=true` и `online-mode=false`. Без явного JVM-флага прежние ограничения не меняются. На integrated/local-in-memory сервере альтернативный режим не включается. Не изменять `requireOnlineModeForPublic`, не использовать `warland.allowOfflineDevelopment` или подмену authlib/Mojang. Whitelist не требуется; `white-list=false`, `enforce-whitelist=false`, RCON/query выключены.

Это отдельный поддерживаемый источник identity, не просто отключение проверки: сервер обязательно выполняет native1.21.11 RSA nonce/AES-CFB8 handshake, выставляя `needsAuthentication=false` только в выбранном режиме. После проверки nonce и включения шифрования используется обычный детерминированный offline UUID; вызова sessionservice нет. Далее остаётся существующий CONFIGURATION barrier: пароль/регистрация, rate limits, reserved owner proof и session binding до создания игрока/профиля/денег. Парольных чат-команд нет. Попытка нового входа не должна отключать уже играющий аккаунт до проверки пароля.

Клиент должен содержать этот же WarLand companion и **заранее полученный публичный** `config/warland/server-fingerprint.txt`: ровно64 lowercase hex SHA256 от DER SubjectPublicKeyInfo. Offline hello без файла/с неправильным ключом отвергается до ответа RSA и до ввода пароля. Если pin установлен, он проверяется и при online hello: изменение флага не позволяет обойти pin. Нет TOFU, автоматического принятия или сохранения пароля. Комплект с pin предназначен для конкретного сервера.

## Идентичность сервера и границы

При первом запуске создаётся `warland/server-identity/identity.bin`: RSA2048, каталог0700, файл0600. Один и тот же ключ сохраняется между рестартами. В журнал разрешён только публичный fingerprint, не private key. Повреждённый файл, ссылки, hardlinks, неверные права, длины или несовпадающая пара ключей блокируют запуск; существующее состояние не заменяется автоматически. Provisioning работает при доверенном локальном сервисном пользователе; это не sandbox против владельца процесса/ОС. Ключ и auth DB включать в приватные резервные копии, не в публичный клиентский ZIP. Ротация ключа требует новой проверенной доставки pin.

Используется штатное шифрование Minecraft RSA/AES-CFB8, **не TLS и не AEAD**, без новых гарантий целостности всех игровых пакетов. Pin подтверждает ожидаемый серверный ключ, пароль подтверждает WarLand аккаунт. Offline UUID не доказывает владение Mojang-аккаунтом. Нельзя смешивать старые online/offline миры, кошельки или владельцев: для альфы отдельные новые данные. Миграция UUID — отдельная задача с подтверждением.

## Владелец

Имя `egorkrid666` зарезервировано существующим AuthRepository. Никакого `op egorkrid666` по неподтверждённому имени. После проверенного запуска оператор через PRIVATE_CONSOLE выдаёт одноразовый bootstrap в приватный0600 файл, передаёт владельцу приватно; владелец вводит код и собственный пароль в companion. Только успешный commit регистрации и текущая авторизованная сессия дают WarLand owner. Код/пароль не размещать в GitHub, логах или публичной сборке. Этот patch не назначает владельца сам.

## Проверки перед открытием

- Сборка exact commit, unit tests и независимый review.
- Позитивный encrypted-offline register→PLAY, restart→login; неверный пароль, nonce/READY, незашифрованный transport, дубликат активного пользователя, fake owner должны быть отвергнуты.
- Стабильный fingerprint после полного рестарта, wrong/missing pin на настоящем companion.
- Отсутствие plaintext secrets в журналах и публикациях; контроль сохранности игроков/инвентаря.
- Пользовательский GUI/client playtest и торговля между двумя аккаунтами — отдельная приёмка, не вывод из headless probe.

Существующие Java-файлы не переписываются: новые mixin adapters расширяют только legacy startup и configuration policy в режиме, где реализован полный encrypted handshake. Требуемые injection points fail-closed (`defaultRequire=1`), нуждаются в настоящем Fabric boot-test, одной компиляции недостаточно.
