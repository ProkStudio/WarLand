# Привязка релизной проверки к установленному JAR

Задача [#21](https://github.com/ProkStudio/WarLand/issues/21), агент `agent-001-20260906-1346`. Это исправление эксплуатационного инструмента, **не релиз, не deployment и не игровая приёмка**. Основная координация — #12, полный checklist — #15.

## Дефект и исправление

В исходном e162219 `tools/release_gate.py` сравнивал evidence с переданным JAR, но не с `RUNTIME/mods`. Два реально выполненных red-теста показали `checklist_complete` при отсутствующем mods и при старом установленном WarLand рядом с новым проверяемым артефактом. Изначальная положительная fixture вообще не создавала mods.

Теперь обязательна стандартная плоская папка `RUNTIME/mods`: ровно один JAR с `id=warland` в Fabric metadata, и его SHA256 должен совпадать с переданным артефактом, который отдельно привязан к evidence. Имя файла не доказывает идентичность мода. Отдельная побайтно идентичная копия допустима; даже две одинаковые установленные WarLand-копии блокируются. Старые 11 gates, online-mode, защитный флаг, 12-часовая мобилизация и ограничения срока evidence сохранены.

```sh
# Linux, Python 3; только в согласованное окно без изменения mods:
python3 tools/release_gate.py RUNTIME APPROVED_WARLAND_JAR EVIDENCE_JSON

# Точечные тесты без Minecraft, сети, сервисов и рабочих данных:
PYTHONPATH=tools python3 -m unittest discover -s tools/tests -p 'test_release*.py' -v

# Полный Python suite из полного checkout:
PYTHONPATH=tools python3 -m unittest discover -s tools/tests -v
```

Код выхода 2 — blocked. `checklist_complete` — проверка заполнения аттестаций и ограниченный снимок дисковых входов, а не доказательство успешного запуска или правдивости evidence. Нельзя подставлять положительные synthetic attestations для допуска живого сервера.

## Консервативные ограничения входов

- Linux descriptor-relative directory walk с `O_NOFOLLOW`; ссылки на моды, каталог mods и компоненты пути к артефакту не обходятся. Hardlinks JAR, устройства, FIFO и каталоги вместо файлов отклоняются. Дескрипторы закрываются и при отказе.
- Поддерживается только плоская раскладка обычных Fabric JAR. Подкаталоги/версийные layouts и не-Fabric JAR блокируются, а не считаются безопасными. Обычные README и `.jar.disabled` игнорируются. Суффикс `.jar` проверяется без учёта регистра для консервативного поиска неоднозначности.
- Не более 512 entries/128 JAR/512 MiB суммы JAR в mods, один JAR до 128 MiB. Metadata — единственная запись `fabric.mod.json`, до 64 KiB; duplicate JSON keys, неверная форма, повреждённые и неподдерживаемые архивы отклоняются. Архивы не распаковываются.
- Metadata и checksum читаются с одного обычного файлового дескриптора. Проверяются изменения inode/size/mtime/ctime во время чтения, замена имени и изменение каталога во время обхода.
- Отчёт не содержит имён подозрительных файлов, JSON metadata, содержимого ссылок, путей к секретам или raw exception messages. БД, playerdata, proof и пароли инструмент не читает.

## Границы доказательств и совместимость

Проверка не блокирует администратору последующую замену файлов и не доказывает, какой JAR уже загрузила работающая JVM. Это не защита от враждебного root или всех параллельных изменений. Перед запуском обязательны GitHub LOCK и отсутствие файловых изменений; проверять установленный набор повторно после deployment, отдельно сопоставляя source/JAR, команду запуска, loader и логи.

Вложенные jar-in-jar зависимости, внешние `fabric.addMods`/альтернативный mods folder, classpath и overrides не разрешаются этим инструментом. Он не эмулирует Fabric Loader и не аттестует зависимости или все конфиги. Их проверка остаётся в runbook/review; стандартный top-level WarLand обязателен. Loader/startup/real-client tests нельзя заменить совпадением SHA.

Это намеренное ужесточение: прежние fixtures/автоматизация без установленного мода теперь получают blocked. Синтетическая positive fixture обновлена на реальный mods-путь, существующие negative assertions не ослаблены. CLI/evidence schema не меняются. Зависимостей, Java, схем и feature flags не добавлено.

- Baseline: 12/12 существующих tests PASS; два новых red-теста по отдельности FAIL с ожидаемым false-positive `checklist_complete` (exit1 каждый).
- После исправления: **47/47 PASS**, включая 35 новых tests; нет skips. Проверены mismatch/missing/duplicates/rename, metadata/corrupt zip, ссылки/FIFO/bounds, замена и изменение во время чтения, отсутствие дескрипторных утечек и изменений файлов. FIFO CLI завершился blocked без зависания и stderr.
- Python compile и `git diff --check` успешны. Полная Java/Python CI этой ветки фиксируется отдельно в PR по точному HEAD; эти локальные 47 не выдаются за весь repository suite.

Локальные логи сохранены отдельно от коммита. CI, независимый review и дальнейшие результаты публикуются в #21/PR, а не угадываются заранее. Это не повторный Fabric boot и не закрытие #17/#19/#15.
