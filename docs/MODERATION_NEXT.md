# Модерация: сохранённые права вместо промежуточных

## Исправлено

Ранее команда меняла `state.roles`/санкции до завершения async save. Теперь команда меняет отдельную копию; роли, муты и блокировки читаются только из последнего подтверждённого snapshot. JSON состояния и audit изменения фиксируются одной SQLite-транзакцией, затем snapshot публикуется на серверном потоке. Одновременно допускается одна запись.

Ошибка/неоднозначный результат записи закрывает модерацию до перезапуска и проверки сохранённых данных. Нет утверждения «операция отменена», если commit неизвестен. Поздний callback после остановки не публикует состояние.

Схема 1, неизменяемые опубликованные карты, UUID/roles/санкции/причины проверяются, ограничены размеры документа и коллекций. Валидные старые документы без schemaVersion принимаются как legacy schema 1 без сброса данных; пустые, повреждённые и будущие схемы не заменяются пустым документом.

`/staff resolve <id> <причина>` закрывает только OPEN-жалобу, причина 8–300 символов сохраняется в audit в той же транзакции. Чтение жалоб повторно проверяет права после async запроса и из старого открытого меню. Родительская интеграция перенаправляет старые `/wladmin reports|resolve` в этот обработчик, чтобы не оставить обход без причины.

## Оставшиеся задачи стадии 6

Полного workflow назначения исполнителя, доказательств/апелляций, полноценного античита и rollback мира ещё нет. Kick и диагностические/read-audit события сохраняют прежний best-effort audit; атомарный audit этого исправления относится к долговечным ролям/санкциям и закрытию жалоб. Авторизация изменения проверяется при отправке; уже подтверждённая транзакция не отменяется задним числом, если затем отозван vanilla OP.

Никаких прав vanilla OP автоматически не выдаётся. Производственный сервер и его данные не менялись.
