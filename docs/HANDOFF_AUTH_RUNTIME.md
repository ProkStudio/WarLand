## Implemented in source (not live-certified)

- `AuthRuntime` connects AuthRepository.start after Store.start and closes Authentication before Store.close. Late startup publication is suppressed after stopping.
- Registration/login use a mandatory Fabric **BEFORE_CONFIGURE** task and configuration-only custom payload. The player does not enter PLAY/the world while pending; no pre-auth profile or starter grant is requested. CoreRuntime additionally checks current authentication inside the profile transaction and again on its callback. Gameplay waits for profile-ready publication.
- Actual `ClientConnection.isEncrypted()` **and** online-mode are mandatory. The original `requireOnlineModeForPublic` guard is retained. Even local offline-development cannot use this credential adapter. No UUID-mode migration is performed.
- `AuthClient` provides a masked registration/login/confirmation/bootstrap screen. Secret fields reject excessive lengths, do not export selections to clipboard, and use a non-secret narration message. Secret input does not go through chat/command history. The client checks the exact current connection handler and encryption before sending. This is a dedicated-server companion, not a singleplayer auth implementation.
- Wire v1: `warland:auth_request`: version byte=1; nonce UUID; operation byte 0=login/1=register; three fields encoded as unsigned-short UTF-16 code-unit count then that many chars (password <=128, confirmation <=128, bootstrap <=43); at most 640 bytes, no trailing bytes. Password must be 12–128 code units; registration confirms before KDF; login rejects extra fields. Client does NOT provide identity/IP. `warland:auth_challenge` carries nonce and status byte 0=prompt, 1=generic denial, 2=accepted.
- Per-connection in-flight flag plus existing bounded KDF/account/peer/global throttling. Connection object, authenticated Minecraft UUID/name, fresh nonce, current handler and expiry are checked; stale callbacks/disconnects cannot authorize a replacement connection.
- Early ClientConnection packet guard, repeated handler-HEAD guards for the pinned play listener methods, and selected asynchronous vanilla publications. Both signed and unsigned command paths reject credential roots/aliases/namespaces and nested execute forms before dispatcher/logging. Credentials are **not exposed as commands**. Completion requests are rejected too. Pending configuration permits only the auth payload and Fabric channel registration/unregistration control payloads; other custom payloads are blocked until admission. Common custom-click/dialog actions are rejected in configuration and rechecked in PLAY.
- Simulation, item pickup, damage/death, menu callbacks, core building/combat/teleports/active time, and stored moderation-role callbacks have additional guards. Session TTL triggers disconnect. This is defense in depth, not proof that every third-party/legacy feature callback is covered.
- `warland-owner-bootstrap` is restricted to the real server console output identity with no entity. Player, command-block, RCON and wrapped-output sources are denied. It creates a 15-minute token only when explicitly executed, writing it to `warland/private-auth/owner-bootstrap.txt` with CREATE_NEW/NOFOLLOW/0600 under a checked 0700 POSIX directory. It never prints the token. Existing file is not overwritten. A trusted operator must privately transfer then delete the file. No command was executed here.
- Maximal WarLand staff permissions require the durably bound owner plus the current authenticated/profile-ready session. Real console remains trusted. No vanilla OP is granted or used as an owner fallback.
- Password reset/change remains deliberately **unexposed**. Do not expose repository.changePassword until reset/login publication and all pending/active-session revocation are serialized and concurrency-tested.
