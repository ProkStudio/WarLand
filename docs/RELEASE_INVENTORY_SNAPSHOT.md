## Исправление

mod_inventory дважды собирает ограниченный no-follow манифест всех непосредственных записей, включая не-JAR: имя, fingerprint файла, mode, nlink. Второй обход выполняется после inspect_mod и повторяет существующие лимиты entries/JAR/суммарного размера. Оба манифеста и fingerprint каталога должны совпасть. Проверки ZIP/metadata/hash/ровно одного WarLand, no-follow дескрипторы и безопасные сообщения CLI сохранены. Старые тесты не изменялись.

## Ограничения и откат

Два обхода не являются атомарным filesystem snapshot или блокировкой concurrent writer. Изменение после последней проверки, ABA и подмена при сохранённых метаданных не исключены. Доказательства относятся к диску, не к загруженному JVM JAR. На время admission/deployment нужны координационный LOCK и исключение записывающих процессов. Сохраняется прежний предел ZipFile: central directory загружается в память в пределах разрешённого размера JAR; это не sandbox для недоверенных модов.

Перезапуск не нужен. Откат — обычный revert этого source/test/doc изменения, без удаления данных/веток и переписывания истории; он вернёт диагностический пробел.
