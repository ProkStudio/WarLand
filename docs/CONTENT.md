# Контент WarLand — вертикальный срез alpha

**Статус:** реальный серверный код для Fabric 1.21.11, собран и протестирован на уровне, указанном ниже. Это **не production-ready реализация всего README**. Production Paper, миры и данные игроков не изменялись; модуль не развёрнут на live.

Проверенный код: `1fe9a1faf9b38fe617f2421392e3042514e032e8`, ветка `feature/content`, база `5424b0c531b2187b18760236478ef10769a49423` (`development/initial-release`). Последующие изменения этого документа не меняют проверенные исходники.

## Реализовано

- `ContentFeature implements Feature`, публичный конструктор без аргументов; серверные callbacks, команды и GUI через `WarLandApi.menu`.
- Новое измерение **`warland:capital`** с пустой flat-генерацией. Автоматическая проверка пустого объёма, порционная оригинальная постройка, сохранение курсора, проверка манифеста перед открытием варпов и после рестарта. **Верхний мир для столицы не используется и не очищается.** При конфликте — пауза, не замена чужого блока.
- Компактная современная Vanilla+ столица: **193×193**, пол Y=80, 16 слоёв с основанием, **87 056 блоков**. Собственные процедуры; сторонних моделей, структур и текстур нет. Постройка сама не создаёт сущностей/NPC. Есть четыре сервисных терминала, три ванильные мишени, полоса препятствий, озеленение с persistent leaves, малые павильоны.
- Два городских чертежа: склад 9×7×6 и мастерская 11×9×6. Частичный предпросмотр контура частицами только владельцу, точная ведомость материалов, отдельное подтверждение покупки, проверка всего свободного объёма/опор/границ/прав, уникальный платёж, этапы резервирования ресурсов, write-ahead журнал пакетов, бюджетное размещение, остановка при конфликте, ручное возобновление после сверки.
- Три ежедневных задания через меню: четыре квартала столицы (+12 реп.), 600 м пешком в Верхнем мире (+16), шесть уникальных чанков (+18). Прогресс наблюдается сервером; бой, полёт, техника, creative/spectator и резкие перемещения не засчитываются. Это консервативная эвристика, **не полноценный античит/антитвинк**.
- Одна репутация столицы и титулы. Предел 120 реп. за неделю; награда и отметка получения сохраняются вместе в одном content state. Денег и предметов за задания нет. Сброс дней/недель по Москве, откат часов назад не сбрасывает уже полученные награды.
- Субботний городской маршрут **18:00–19:00 МСК**: восемь точек по порядку, минимум 200 м и 90 с, промежутки от 8 с, +25 реп. один раз в неделю в общем недельном лимите. Это настоящее небольшое прогулочное событие, не босс/конвой/PvP-событие.

## План столицы и перемещение

Палитра: гладкий камень/кварц, полированный глубинный сланец, окисленная медь, голубое стекло, цветная терракота, тёплое дерево. Низкие открытые навесы, центральный сухой монумент, широкий крест дорог и внутреннее кольцо. Никаких фонтанов, редстоун-часов, сотен NPC или импортированных schematic.

После проверки регистрируются `spawn` через `setSafeSpawn` (радиус 128), а также `capital`, `capital_market`, `capital_quests`, `capital_transport`, `capital_training`. GUI **не телепортирует напрямую**: выполняет `/spawn` или `/warp` от лица игрока, сохраняя правила ядра о бое, задержке, цене и отмене. Внутри готового измерения есть отдельное спасение упавшего ниже платформы игрока с высадкой из техники.

Пешая доступность всех прибытий, свободное место для ног/головы и опоры декора проверены тестами. План сверху визуально проверен: исправлены угловые деревья вне основания и лавка на точке прибытия штаба. **Скриншота/визуального осмотра в Minecraft-клиенте пока нет.** Зал славы и демонстрационный павильон — только архитектура, не фиктивные сезонные рейтинги/рабочая техника.

## Строительство: экономика и ограничения

**`buildingPurchasesEnabled=false` по умолчанию. Не включать на public до объединения с общим inventory journal/lock и аварийных испытаний.** Предпросмотр доступен без списаний. Склад стоит 600 единиц валюты API + 270 фактических блоков; мастерская — 1000 + 404 блока и требует 40 репутации. Цены пилотные, не откалиброваны под рынок.

Ресурсы равны точному количеству каждого блока в плане, включая плиты, стекло, светокамень, бочку и рабочие столы. Принимаются обычные непереименованные стеки с компонентами стандартного предмета из 36 основных слотов. Проверка режима игрока не доказывает происхождение предметов: выдачу администратором без метки от добычи отличить нельзя.

- Только Верхний мир и ровная сухая сплошная опора; весь объём должен быть AIR. Даже траву модуль не удаляет. Вход фиксирован на север (−Z); поворота/терраформинга нет.
- `canBuild` проверяется в полном объёме и при каждом блоке; пересечение зарегистрированных зданий запрещено. Текущий API допускает wilderness: **это ещё не проверка city membership, ранга или уровня города**.
- Одновременно до четырёх незакрытых работ глобально, одна на игрока; до трёх неотменённых зданий на игрока, журнал до 128 работ. Паузы/сверки занимают лимит; автоматического архива и таймаута брошенных работ пока нет. В GUI показаны последние 18 работ.
- Владелец должен находиться в том же мире, вне боя/техники и не дальше 64 блоков. Городские чанки не форсируются. Контур — не гарантия покупки: проверки повторяются после асинхронных ответов.
- Пользователь может отменить предпросмотр бесплатно. После оплаты возможен подтверждённый отказ **без возврата**, с сохранением уже поставленных блоков. Частичный возврат и автоматический снос отсутствуют.
- Нет пассивного дохода, автопочинки, бесплатного восполнения добытых блоков, стакающихся бонусов и кредитования денег при отмене. Полезность построек — обычные ванильные хранилище/рабочие места.

## Хранение и честный протокол восстановления

Все метаданные: `getState/setState`, namespace `content`, key `state.v1`, schema 1. Внутри — валидируемая Config v1, capital, jobs, profiles. Один последовательный writer, очередь ограничена 64 запросами. Ошибка/неизвестная схема не перезаписывает данные и прекращает дальнейшие операции. Ввод-вывод через API асинхронный; callbacks мира возвращаются в серверный поток, `join/get` в тике нет.

Покупка: `CHARGING` → идемпотентный debit `content:building:<UUID>:payment:v1` → `WAITING_MATERIALS` → сохранённый `MATERIAL_INTENT` → изъятие предметов → `PLACING`. Перед пакетом сохраняется `BATCH` с границами; после — курсор. Деньги повторно не списываются при обычном продолжении.

**Инвентарь, чанки Minecraft и SQLite не составляют одну транзакцию.** Полного before/after snapshot инвентаря и общего lock с торговлей здесь нет. Нет заявления exactly-once между этими хранилищами.

После любого рестарта незаконченные финансовые/мировые операции консервативно переходят:

- `CHARGING` → `PAYMENT_REVIEW`: персонал сверяет журнал; повтор использует тот же ID платежа.
- `MATERIAL_INTENT` → `MATERIAL_REVIEW`: неизвестно, сохранилось ли изъятие. **Автоматического повторного изъятия, возврата или выдачи блоков нет.**
- `PLACING/BATCH` → `RECOVERY`: сверить чанки, инвентарь/бэкап, платёж и границы пакета. Команда восстановления — явное удостоверение персонала, не автоматическое доказательство.
- `WAITING_MATERIALS` сохраняет факт оплаты; игрок может донести ресурсы. `DONE/ABANDONED` никогда автоматически не возобновляются.

Во время активной работы ручные break/use защищены; последний загруженный снимок защиты сохраняется и при отказе хранилища. Защита от взрывов, поршней, огня, жидкостей и других модов требует ядра. Самовосстановления столицы после потери/изменения сохранённых блоков нет: проверка останавливается. Естественные distance листьев, соединения стен и кратковременная мощность мишени не считаются чужим блоком.

## Подключение к ядру

1. Загрузить `ru.warland.content.ContentFeature` без аргументов. `initialize(api)` один раз при mod initialization; `serverStarted(server)` после готовности БД; `tick(server)` один раз за серверный тик; `stopped()` до закрытия БД. Отдельная запись content в `fabric.mod.json` не нужна, если используется загрузчик Feature ядра.
2. Команды: `/capital`, `/capital status`, `/citybuild`, `/quests`, `/rep`, `/events`. Staff permission: `warland.content.admin`. Админ-команды: `/capital budget 8..256`, `/capital resume <причина 8–160 символов>`, `/citybuild purchases true|false`, `/citybuild recover <UUID> <причина>`.
3. Конфликт UseBlock с ранним veto ядра **решён в модуле через Fabric event phase** `warland:content_terminals` перед `Event.DEFAULT_PHASE`; порядок initialization менять не требуется. Только точные координаты терминалов открывают read-only GUI; обычное использование блоков столицы остаётся запрещено. Контракт порядка фаз покрыт тестом. Совместимость с inventory guards других модулей проверить на staging.
4. Ядро должно защищать **всё `warland:capital` уже во время генерации**, а не ждать `setSafeSpawn`: блоковый урон взрывов, fire/lightning, fluids, pistons, сущности/транспорт. Content не редактирует общие protection mixins. Территории строительства также требуют серверной защиты ядра.
5. Для нового игрока назначение точки первого входа и core tutorial eligibility остаются ядру. `/capital` tutorial не меняет core-поле допуска к созданию государства; для него существует `/warland tutorial`.
6. До полного завершения проверки столичный варп отсутствует. При подготовке пустого сервера нужен продолжающийся тик (например, отключённая пауза пустого сервера либо подключённый тестовый игрок). Отсутствующее измерение не заменяется Верхним миром.

## Бюджеты и конфигурация

По умолчанию 64 размещения/пакет, 512 проверок/проход, мягкий предел 1500 мкс между операциями. У столицы один временный non-serialized loading-only chunk ticket; обновление раз за чанк за тик; освобождение при переходе/остановке. Preview — до 20 точек раз в секунду плюс начальный показ, только смотрящему игроку, без preview entities. Это не гарантирует MSPT отдельного внутреннего вызова Minecraft.

Config v1 хранится вместе с state; размеры/лимиты/цены валидируются. Покупки и бюджет доступны staff-командами. Часть правил наград/расписания пока константы `ActivityRules`, внешнего TOML/JSON5 и полного live-reload нет. Не редактировать state параллельно с работающим единственным writer.

## Проверено и ещё не проверено

Последняя проверка: **`clean test build` — BUILD SUCCESSFUL**, 38 с, Java 21, Gradle 9.2.1, Loom 1.14.10, Yarn 1.21.11+build.6, Loader 0.19.5, Fabric API 0.141.6+1.21.11. **52 теста прошли, 0 ошибок/падений, 4 runtime-only теста явно отключены.**

Покрыты: уникальность/детерминизм блоков, точная ведомость, отсутствие AIR/жидкостей/опасных блоков в планах, опоры и маршруты, коллизии/права, режимы восстановления, неподтверждённые материалы, повторные награды, недельные/московские границы и откат времени, async очередь/отказ записи/закрытие/неизвестная схема, контракт фаз Fabric, JSON пустого измерения.

Попытка реального bootstrap Minecraft registry в обычном Loom/JUnit выявила `IllegalAccessError` на `RegistryEntry.Reference.setRegistryKey`: plain test JVM не применяет требуемые Fabric/Knot access transformations. Четыре проверки реестров/блоков/DimensionOptions codec сохранены с явным `@Disabled`, **не посчитаны пройденными**. Для них нужен корректный Fabric/Knot/GameTest harness. Это не заменено фальшивым «всё работает».

Обязательные оставшиеся gates: boot/headless и клиентский smoke с ядром, загрузка codec измерения, физическое завершение/рестарт столицы, GUI/инвентарь и guards, аварии во всех фазах purchases, действия поршней/жидкостей/взрывов, отказы БД и нагрузка 10/20/30 игроков. На live ничего из этого не выполнялось. **Custom enchantments, city tiers/upkeep/upgrades, полноценные фракции, боссы/конвои/PvP-events, season hall data, ресурспак и клиентский HUD не реализованы.**

## Безопасный откат

Сначала выключить новые покупки и не открывать production. Сохранить согласованный бэкап БД/state, инвентарей и dimension на остановленном тестовом сервере. Сверить незаконченные операции — не удалять журнал ради повторной оплаты/выдачи. Для отката кода отключить загрузку Feature/вернуть предыдущий проверенный JAR через процедуру ядра, сохранив данные и определение уже использованного измерения; сначала вывести из него игроков. **Не удалять region-файлы и не сбрасывать state/курсор для автоматической пересборки.** Удаление мира/несовместимая миграция требуют отдельного решения владельца.
