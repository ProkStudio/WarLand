# Приватная консоль systemd без RCON

`tools/private_console.py` решает конкретную эксплуатационную проблему: systemd-сервис без интерактивного stdin теперь может получить настоящую локальную консольную команду. Скрипт не создаёт владельца автоматически, не выдаёт OP, не включает online/offline-флаги и не заменяет какой-либо работающий сервис.

## Граница доверия

- Только Linux AF_UNIX: нет TCP-порта, HTTP, RCON, пароля или удалённого подключения.
- Каталог сокета принадлежит сервисному пользователю и имеет **0700**; сокет и lock-файл — **0600**. Ссылки, небезопасные режимы, другой владелец, hardlink lock-файла и существующий путь сокета отклоняются.
- Один экземпляр держит `flock`; создание/удаление идёт через открытый дескриптор каталога. При завершении удаляется только собственный inode сокета. Чужой или заменённый файл не удаляется.
- Клиент и сервер проверяют Linux `SO_PEERCRED`. Отправлять команды разрешено root и самому сервисному пользователю. Это сознательная консольная власть ОС, а не разрешение любому игроку или сетевому адресу.
- JVM работает без root, запускается без shell. Скрипт не переписывает Java environment и не подставляет тестовые identity-provider.
- Одна команда не больше 2048 UTF-8 байт. Переводы строк, управляющие/невидимые форматирующие символы, лишние команды и некорректный UTF-8 отклоняются. Длина/время приёма и очередь ограничены; pipe записывается неблокирующе.
- Ответ `queued` означает **только очередь передачи в stdin, не успешное исполнение Minecraft-команды**. Текст команд не отражается в ответах/ошибках скрипта. Игровую обратную связь проверять в приватном журнале сервиса.
- Если ответ потерялся, команда могла попасть в очередь. Не повторять финансовые/владельческие операции вслепую: сначала проверить фактическое состояние.

## Установка оператором

Пример `ops/warland.service.example` предназначен для нового проверенного развёртывания, не для автоматической подмены Paper или прежнего staging. Код инструментов хранить в `/opt/warland/app` с записью только у root; игровой runtime — `/opt/warland/runtime` у пользователя `warland`. systemd создаёт `/run/warland` с нужным владельцем и режимом. Python 3 — системный, сторонние зависимости не нужны.

```sh
# После установки и запуска проверенного systemd-unit:
sudo -u warland python3 /opt/warland/app/tools/private_console.py send \
  --socket /run/warland/console.sock 'list'
```

Для операционного shutdown использовать `systemctl stop warland`: wrapper передаёт `stop`, ждёт штатный выход до 60 секунд, и только затем принудительно завершает собственную process group. Такой timeout даёт код **124** и НЕ считается сохранённым/штатным shutdown. `KillMode=mixed` оставляет Minecraft возможность завершиться через stdin, `TimeoutStopSec=90` ограничивает всё завершение. Код ошибки дочернего процесса сохраняется. Команды, ещё не начавшие запись при остановке, отбрасываются; уже начатая строка заканчивается перед `stop`.

После SIGKILL может остаться сокет. Скрипт не удаляет его автоматически. systemd управляет жизненным циклом `/run/warland`; при ручном запуске оператор сначала обязан убедиться, что процесс и владелец lock не работают. Не удалять чужие файлы ради запуска.

## Приватная привязка владельца — только отдельное действие

Команда `warland-owner-bootstrap` может быть отправлена тем же локальным каналом **только когда действительно нужна привязка владельца**. Она проходит настоящие Minecraft console/source проверки и создаёт proof в `warland/private-auth/owner-bootstrap.txt`, а не в чате. Скрипт его не читает и не возвращает. Передача proof владельцу остаётся приватной операционной процедурой; ник сам по себе не доказывает личность. В этом изменении реальный bootstrap не выполнялся и владелец не назначался.

Никогда не передавать пароли через консоль, shell-аргументы, GitHub или логи. Регистрация/вход остаются в защищённом companion-интерфейсе.

## Проверки и предел доказательств

```sh
PYTHONPATH=tools python3 -m unittest discover -s tools/tests -v
```

Добавлены unit/OS-тесты framing, Unicode/размера/управляющих символов, таймаутов, SO_PEERCRED, прав/ссылок/lock/cleanup, backpressure и shutdown-очереди. Отдельный реальный дочерний процесс получает русскую строку через stdin, отвергает многострочную инъекцию и штатно завершается через stop после SIGTERM wrapper.

Эти тесты **не Minecraft-приёмка**. Проверку с точным Fabric JAR, console-source и синтетическим proof фиксировать отдельно после исполнения, с новым QA-каталогом. RCON/command-block/function источники этим инструментом не объявляются проверенными. Рабочие миры/сервисы и секреты тесты не используют.
