## Совместимость и исправления

Для Fabric/Minecraft 1.21.11 в командах заменены недопустимые составные объявления `var` на `ServerPlayerEntity`, а вызов старого `executeWithPrefix` — на `parseAndExecute`. Обработчик разрушения блока получает `World`: перед передачей в API ядра он явно проверяет `ServerWorld` и закрывает действие при неподходящем серверном мире.

Шесть доменных дефектов закрыты регрессионными тестами:

1. `Math.abs(Long.MIN_VALUE)` обходил валидацию суммы. Теперь `Store.change` проверяет обе знаковые границы ±1 000 000 000 000 до записи счёта. SQL-ограничение баланса и раньше предотвращало отрицательный баланс; дефект был именно в валидации и побочном создании счёта.
2. `Rules.claimLimit` переполнял `int` до применения лимита 256. Промежуточные вычисления теперь выполняются в `long`.
3. `Rules.price` переполнял `base * percent` для больших `long`. Разложение на частное и остаток сохраняет целочисленное округление, минимум 1 и исходный диапазон процентов.
4. `Store.tx` откатывал `Exception`, но не `Error`: восстановление autocommit могло зафиксировать частичную операцию. Теперь откатываются обе категории; тест бросает `AssertionError` после списания.
5. Создание государства вне Верхнего мира блокировалось командой, но не самим сервисом. Проверка добавлена на доменной границе.
6. Повтор команды пакта позволял одной стороне заменить действующий `PACT` на `OFFER`. Действующий пакт теперь нельзя понизить или продлить односторонним повтором; после истечения снова требуется взаимное согласие.

## Стенд и воспроизведение

- OpenJDK 21.0.12, `release=21`.
- Minecraft 1.21.11; Yarn 1.21.11+build.6; Fabric Loader 0.19.5; Fabric API 0.141.6+1.21.11.
- Gradle 9.2.1; Loom 1.14.10; SQLite JDBC 3.49.1.0; JUnit Jupiter 5.11.4.
- Отдельная копия `/opt/warland-build/coreqa`, пользователь `warland-build`, общий Gradle cache и `flock` для последовательной сборки.
- Один Gradle worker, heap сборки 768 MiB, тестов 256 MiB; дочерняя JVM crash-теста — 64 MiB. Сервер Minecraft для этих проверок не запускается.

Из корня репозитория, под непривилегированным build-пользователем:

```bash
env GRADLE_USER_HOME=/opt/warland-build/.gradle \
  flock /opt/warland-build/build.lock \
  /opt/warland-build/tools/gradle-9.2.1/bin/gradle \
  --no-daemon --max-workers=1 clean build
```

Повторное выполнение, не результат из up-to-date/cache:

```bash
env GRADLE_USER_HOME=/opt/warland-build/.gradle \
  flock /opt/warland-build/build.lock \
  /opt/warland-build/tools/gradle-9.2.1/bin/gradle \
  --no-daemon --max-workers=1 test --rerun-tasks
```

На другом компьютере нужны те же JDK/Gradle и обычный `gradle --no-daemon --max-workers=1 clean build`; абсолютные пути выше относятся только к QA-стенду. Длительные команды на стенде запускались в фоне с логами и конечной проверкой кода выхода.

Crash-тесты запускают отдельный Java-процесс и вызывают `Runtime.halt` после SQL-изменения до commit либо после завершённого commit. Родительский процесс проверяет ненормальный код выхода, наличие незавершённого WAL, восстановленный баланс/ledger и повтор операции. Это реальный abrupt process exit на **временной БД**, но не тест отказа диска, питания VPS, повреждения ФС или живого Minecraft-сервера.

Проверено полное совпадение опубликованных пяти Java-файлов с исправленной копией стенда; SHA-256 трёх файлов RulesBoundaryTest, StoreBoundaryTest и NationsServiceTest совпал с локально подготовленными файлами. Оба финальных прогона выполнялись непосредственно на опубликованном коммите с StoreCrashRecoveryTest. Материалы прогонов остаются в `/opt/warland-build/coreqa-evidence/`; БД, build-каталоги и raw логи в репозиторий не добавляются.

Проверен core-артефакт `build/libs/warland-0.1.0-alpha.1.jar`: 14 382 288 байт, SHA-256 `a0e78788eaaa776406ef72b513d85ab56caf09372b0a0346cea08e16bb80a015`. Внутри есть все пять исправленных классов и вложенный SQLite JDBC. Это артефакт указанного QA-коммита, **не финальная интегрированная сборка content/market/combat**.

Предупреждения сборки: версия SQLite JDBC из четырёх компонентов не является semver для сообщения Loom; присутствует предупреждение о deprecated Gradle features перед Gradle 10. Эти предупреждения не заменяют runtime-проверку зависимостей.

## Оставшиеся ограничения и следующие gates

1. **Игровые проверки не выполнены этим QA.** Не проверены реальные клиенты, GUI/shift-click/drag, Minecraft/Fabric mixin injection, placement/explosion/fluid/piston callbacks, отключение игрока, сохранение мира и совместная работа content/market/combat. Компиляция не доказывает защиту от всех игровых обходов.
2. **Активные жители и защита от твинков пока упрощены.** Лимит использует `profiles.last_seen` за 7 дней, а не минимальное время игры в скользящем окне. Нет требуемого периода новичка помимо tutorial, 7-дневного grace для сверхлимитных территорий и повышенного содержания.
3. **Unicode case folding не решён.** SQLite `NOCASE` регистронезависим только для ASCII; русские названия валидны, но `Север`/`север` могут быть разными названиями. Нужны единая нормализация во всех lookup, политика существующих коллизий и отдельно проверенная миграция; схема здесь не менялась.
4. **Аудит не полный.** Финансовые операции записываются в ledger и покрыты тестами; изменения рангов, налогов и дипломатии ещё не записываются атомарно в `audit`, хотя README это требует.
5. Полный жизненный цикл государств (исключение/передача лидерства/роспуск/освобождение территории), другие виды договоров и роли модерации остаются задачами интеграции. Эта серия не подменяет их готовыми возможностями.
6. Не выполнены нагрузка 30 игроков, измерения TPS/MSPT и восстановление боевого мира из backup. Значения времени выше — длительность сборки, а не игровые показатели.
7. Флаги `enableBuyer`, `enableAuction`, `enableWarCapture` этим QA не включались. Допуск к запуску требует проверки текущего интегрированного дерева, runtime и всех эксплуатационных gates README.

## Откат

Ничего не установлено в runtime, поэтому откат служб или мира не требуется. Схема остаётся версии 1; миграций/удаления данных нет. Для отмены серии исходников используйте отдельную ветку и обычный reviewable revert соответствующих коммитов, учитывая зависимости тестов. Полный откат коммита исправлений вернёт и ошибки компиляции 1.21.11, и воспроизведённые дефекты — это **не безопасный путь deployment rollback**. Для runtime всегда нужен ранее проверенный полный артефакт и процедура операционного отката основной команды.
