# Эксплуатация: восстановление и контроль допуска

## Проверенное восстановление

`tools/restore_snapshot.py` проверяет SHA-256 и разворачивает архив **только в новый каталог**. Существующие каталоги и ссылки назначения не заменяются. Скрипт не управляет systemd и не запускает Minecraft.

```sh
python3 tools/restore_snapshot.py /backups/warland-DATE.tar.gz /restore/new-copy
# Если checksum не расположен рядом в .sha256:
python3 tools/restore_snapshot.py /backups/warland-DATE.tar.gz /restore/new-copy --sha256 EXPECTED_SHA256
```

- Принимаются только обычные файлы/каталоги: traversal, абсолютные пути, ссылки, устройства, FIFO, sparse-файлы, дубли и конфликты file/directory отклоняются.
- По умолчанию не более 200 000 записей и 20 GiB распакованных данных; параметры `--max-files` и `--max-gib` задаются оператором.
- Проверяется наличие базового runtime и `warland/warland.db`, свободное место, SQLite `quick_check` и `foreign_key_check`. Время SQL-проверки ограничено progress handler.
- Новый каталог закрыт правами 0700, файлы 0600. Владелец — пользователь, запустивший восстановление. Сервис после проверки должен запускаться от предназначенного непривилегированного пользователя, не от root.
- При отказе удаляется только созданный самим скриптом новый каталог. Исходный архив и существующий runtime не меняются.
- JSON-отчёт `restore-verification.json` не содержит игровых данных. Он подтверждает распаковку и целостность БД, **не игровой boot**. Проверку запуска проводить отдельно, в изоляции.

Снимок должен быть согласованным: используйте штатно остановленный runtime и существующий `tools/backup.sh`. Проверка checksum не делает горячую копию мира атомарной. Не публикуйте архивы и логи с player data.

## Read-only проверка допуска

```sh
python3 tools/release_gate.py RUNTIME WARLAND_JAR EVIDENCE_JSON
```

Команда не деплоит, не включает покупки, не меняет конфиги и не запускает сезон. Она проверяет online-mode, публичный защитный флаг, 12-часовую мобилизацию, версию артефакта и заполненность аттестаций приёмки. Код выхода 2 означает блокировку. `checklist_complete` означает только корректно заполненный чек-лист, а не автоматически доказанную готовность.

В evidence нужны `schema: 1`, `artifact_sha256`, `recorded_at` с часовым поясом и объект `gates`. Для каждого gate нужен объект `passed` (строго boolean), `evidence` (ссылка/путь к результату), `verified_by` (кто проверил). Дата должна быть не из будущего и не старше семи дней; checksum относится к конкретному JAR.

Gates: `functional_stages_0_6`, `inventory_crash`, `war_permissions`, `vehicle_restart`, `client_visual`, `load_10`, `load_20`, `load_30`, `restore_boot`, `economy_balance`, `owner_cutover_approved`.

**Это аттестации оператора. Скрипт не проверяет правдивость приложенных утверждений и не заменяет игровые тесты.** Непройденным пунктам оставлять `passed: false`, а не заполнять их ради зелёного результата. Переход старых offline UUID и переключение production требуют отдельного решения владельца.

## Автоматическая сборка

`.github/workflows/build.yml`: Java 21, pinned Gradle bootstrap, `clean test build`, Python-тесты эксплуатационных инструментов; артефакт JAR и JUnit XML хранятся 14 дней. Разрешение workflow — только contents:read, нет секретов, SSH или деплоя, credentials checkout не сохраняются. Pull request запускается как `pull_request`, не `pull_request_target`.

CI не выполняет Minecraft-клиент, нагрузку или аварийную приёмку. Статус реального запуска CI нужно смотреть в GitHub, а не выводить из существования workflow.

## Результаты 06.09.2026

- 30 Python-тестов (18 восстановления и 12 release checklist) прошли в sandbox и повторно на VPS из опубликованных файлов; контрольные суммы исходников совпали.
- Архив ранее штатно остановленного **синтетического** runtime: 295 записей, 183 939 937 распакованных байт. Восстановлена отдельная копия, SQLite-проверки прошли.
- Из восстановленной копии отдельно запущен dedicated Fabric на loopback: `Done`, `WarLand ready`, затем штатное сохранение и завершение; ERROR и необработанных исключений не обнаружено.
- SHA-256 тестового архива: `391f8021ab966558c8bf41779d1e12d77ae7b33314e1a0455ac5b9d3d98ecd5b`. Архив не публиковался. Это проверка механизма на тестовом мире, не заявление о восстановлении всех production-данных.
- Рабочий Paper не заменялся. Регулярный backup timer, retention и публичное переключение не включены без согласованного окна обслуживания.

```sh
PYTHONPATH=tools python3 -m unittest discover -s tools/tests -v
```
