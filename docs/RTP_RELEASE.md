# WarLand 0.1.0-alpha.3.2 — безопасный /rtp

Предварительный серверный патч, НЕ полный stable-релиз. Minecraft Java 1.21.11, сервер Fabric/Java21; клиенту моды не нужны. Существующие аккаунты, парольная форма и ресурспак сохраняются. Перевод входа в чат, новое лобби/крепость/TAB/HUD и остальные требования полного ТЗ этим патчем не объявляются завершёнными.

## Изменения
- Подключён `/rtp`: бесплатно, на поверхность обычного мира в кольце1000–3000 блоков от его спавна. Интервал180сек хранится в SQLite по аккаунту и переживает reconnect/restart.
- Суша, полноценный устойчивый пол3×3, свободное пространство и проверка опасностей5×5; исключены жидкости, опасные блоки, чужие и собственные приваты с соседними чанками, выход за границу мира и коллизии. Блоки мира не перестраиваются.
- Отмена при движении, смене мира/сессии, выходе, уроне/бое, параллельном warp, операции с инвентарём, технике и боевом окне государства.
- Один общий запрос, ограниченные попытки/время/асинхронные chunk tickets без синхронного getChunk. Если безопасная точка не найдена, телепортации нет. Генерация чанка всё равно требует ресурсов Minecraft; это не обещание отсутствия нагрузки.
- Ожидание записывается перед переносом. Если отмена совпала с уже принятой записью, cooldown консервативно остаётся; `/rtp` покажет остаток. Деньги не списываются.
- Исправлены три ложных падения тестов из-за совпадения имени HAZARD у fixture и enum; добавлена проверка подключения при запуске.

## Обновление существующей alpha.3/alpha.3.1
Этот комплект — серверный patch, НЕ новый full installer. Для чистой установки остаётся проверенный installer alpha.3, после него применяется данный patch. Fabric/API/Polymer/Java/resource-pack остаются прежними; клиент ничего вручную не устанавливает.

1. Проверить SOURCE_COMMIT и `sha256sum -c SHA256SUMS`; executable — JAR без `-sources`.
2. Проверить отсутствие игроков; штатно остановить ТОЛЬКО выбранный WarLand-сервис и убедиться, что JVM закончилась.
3. Сделать приватную полную резервную копию runtime и проверить архив/восстановление. Не публиковать миры/БД/ключи/пароли.
4. Сохранить прежний WarLand JAR ВНЕ mods; установить ровно один новый executable JAR. Не менять конфиги, accounts/worlds, server identity и owner/OP.
5. Запустить, проверить ready/version/logs/data, выполнить контролируемый smoke. Для данного VPS использовать service-bound ops и общие build/backup locks, не расширять allowlist старого backup.sh.

Откат — штатно остановить сервис и вернуть только прежний JAR, сохранив все новые данные игроков. Новая схема БД не вводится: cooldown использует существующую state-таблицу. Старую БД поверх новых действий не восстанавливать. Старые релизы/tags/assets не перезаписывать.
