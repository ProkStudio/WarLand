# План реализации и границы допуска

ТЗ: ../README.md. Это ветка разработки, не объявление готового сервера.

## Проверенная основа

На 05.09.2026 официальный Fabric Meta подтверждает Minecraft 1.21.11, Loader 0.19.5 и Yarn 1.21.11+build.6; Maven Fabric содержит API 0.141.6+1.21.11 и Loom 1.14.10. Gradle 9.2.1, Java release 21. На VPS обнаружен Paper 1.21.11. Переход на Fabric выполняется через отдельную директорию и сохранение исходной копии мира; форматы Paper Nether/End нужно преобразовать на копии, не на оригинале.

## Архитектура

Feature -> WarLandApi -> core/services -> SQLite. UI и мир изменяются только серверным потоком; БД обслуживает выделенный последовательный executor. Ledger и операции имеют уникальные ключи. Деньги — целые игровые кредиты (long), не float. SQLite WAL + synchronous FULL. Вещи между инвентарём и БД требуют durable intent/escrow и восстановления, а не заявления о распределённой атомарности.

Модули: core/data/economy/nations/claims/war; combat/vehicles; cities/content/quests/events/enchantments; moderation/ops. Клиентские renderer-классы не загружаются dedicated server. Все необязательные системы должны выключаться конфигурацией.

## Стартовый баланс (проектные значения)

Старт: 1500 кредитов. Создание государства: 1000. Первый чанк при основании включён; последующие: 100. Лимит: 9+3*активные жители+бонус уровня. Налог: 0–15%, повышение с задержкой 24 часа. Война: 5000, мобилизация 12 часов, окно по Москве 19:00–21:00, продолжительность не менее 72 часов после мобилизации. Значения уточняются в отдельных конфигах и тестах; нагрузка 30 игроков ещё не проверена.

## Жизненные циклы

Профиль: создан -> обучение -> активен. AH: intent -> escrow -> listed -> sold/expired/cancelled -> mailbox -> claimed. Здание: preview -> paid intent -> placing -> active -> upgrade/damaged. Война: declared -> mobilizing -> window/truce -> settled -> immunity. Техника: owned -> deployed -> parked/destroyed. Конечные статусы не должны отменяться повторным сетевым запросом.

## Схема и конфиги

Таблицы: migrations, accounts, ledger, state(namespace,key,json), nations, members, claims, invitations, wars, listings, mailbox, pending_inventory, reports, sanctions. Конфиг core содержит лимиты/цены/периоды; отдельные content-каталоги содержат здания, квесты и оружие. Локальные секреты, базы, миры, списки игроков и бэкапы не публикуются.

## Этапы и quality gates

1. Сборка Java/Fabric и unit-тесты domain/SQLite.
2. Экономика, государства, приваты и меню; проверки полномочий и идемпотентности.
3. Здания, оружие, транспорт и события; отдельные серверные и клиентские проверки.
4. Изолированный сервер 127.0.0.1:25566, load/save/restart и тестовый клиент.
5. Только после прохождения проверок — кандидат на переключение. Не выдавать alpha за завершённое ТЗ.

## Риски и ограничения

4 ГБ — суммарная память VPS, не доступный Java heap. Компиляция идёт с одним worker и малым heap; тестовый сервер не работает параллельно с нагрузочной сборкой. Предгенерация радиуса 6000 отложена до измерений; не делать её автоматически на работающем VPS. Исходный Paper использует offline-mode: его нельзя переносить на публичный экономический сервер без решения аутентификации. Миграция UUID при online-mode может менять идентичность; исходные данные сохраняются.

Внешних моделей нет; используем оригинальные низкополигональные кубоидные модели. Юридическая совместимость сторонних ассетов проверяется до включения. Fabric API и SQLite — технические зависимости, не готовый игровой модпак.

## Тестирование

Unit: баланс/переполнения/идемпотентность, изоляция account, сохранение ledger, claim/war math. Integration: повторные запросы, restart, permissions, инвентарный escrow, disconnected callback, слоты GUI (shift-click/drag/number-key). Deployment: backup verify, version, мод загружен, отсутствие ошибок, rollback. Нагрузочный тест 10/20/30 реальных клиентов и визуальная проверка моделей — отдельный gate, не подменяется idle TPS.
