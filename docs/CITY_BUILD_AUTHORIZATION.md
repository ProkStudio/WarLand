# Права городского строительства — проверенный срез 06.09.2026

База: `f079b39857e55673d8888d702dbdbd8fce97e031` (`development/initial-release`). Код исправления: `851da1c7ca80aaece122cd76a10d160bdf91c210`.

Этот документ уточняет исторические пункты CONTENT.md и INTEGRATION_CORE.md о ещё не подключённом `canBuildCity`: в данном срезе связка подключена. Это не разрешение включить покупки на публичном сервере.

## Что изменилось

- BuildingService использует `canBuildCity`, а не общую проверку `canBuild`, которая допускает wilderness. Сохраняется политика ядра: собственный приват, членство и право строительства; safe zones и блокировка инвентаря не обходятся.
- Проверяется весь объём чертежа, включая пустое внутреннее пространство, и слой основания. Не только точка начала и не только блоки, которые будут поставлены.
- Проверки повторяются при подтверждении, после ответа баланса, после сохранения первоначального CHARGING и до вызова debit, до MATERIAL_INTENT, после его сохранения перед изъятием материалов и после записи BATCH перед размещением. Каждый размещаемый блок дополнительно проверяется отдельно.
- Потеря прав до первого вызова debit завершает неоплаченный заказ без списания. PAYMENT_REVIEW не объявляется неоплаченным: неопределённый платёж по-прежнему разрешается с тем же ID операции. Возврат не придумывается.
- Уже оплаченная работа при недоступности площадки/отключённых покупках ожидает материалы без их изъятия и без повторного платежа. При отказе после записи MATERIAL_INTENT, но до изъятия, возвращается WAITING_MATERIALS. При потере прав перед размещением работа переходит в PAUSED; блоки не удаляются.
- Проверяются готовность ядра, inventory lock, измерение, расстояние, загруженность чанков, высота мира и world border. Проверка площадки не загружает чанки.
- BuildingSiteRules ограничивает синхронную проверку 1024 позициями. Существующие чертежи укладываются; слишком большой/некорректный план и переполнение координат запрещаются. Это предел количества проверок, не гарантия MSPT. Первый блок пакета может быть проверен даже после расходования мягкого временного бюджета, чтобы работа не застревала навсегда.

```sh
GRADLE_USER_HOME=/opt/warland-build/.gradle \
  /opt/warland-build/tools/gradle-9.2.1/bin/gradle \
  --no-daemon --max-workers=1 clean test build
```

- Финальная чистая сборка: **BUILD SUCCESSFUL**, 42 секунды, Java 21 / Gradle 9.2.1 / Loom 1.14.10.
- JUnit XML: **161 обнаружен, 157 успешны, 4 пропущены, 0 failures/errors**. Четыре существующие runtime-only проверки не объявляются пройденными.

Последние читают исходник; они не заменяют тест с Minecraft-игроком.

## Что ещё не доказано и не включено

`buildingPurchasesEnabled=false` остаётся значением по умолчанию. Общий inventory journal/escrow и блокировка всех способов перемещения предметов, аварийное восстановление, реальный клиентский тест отзыва прав во время покупки, завершение всей столицы, нагрузочная и визуальная приёмка не выполнены в этом срезе. Boot проверяет совместимость загрузки, не корректность покупки игроком. City tiers, upgrades и пассивный доход этим изменением не добавлены.

Следующий безопасный этап: общий журнал инвентарных операций и его аварийные тесты в изоляции; затем клиентские сценарии покупки/продолжения при изменении прав. Не переносить код на public и не открывать покупки только на основании этого отчёта.
